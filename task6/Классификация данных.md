### Логика работы движка классификации данных
| Этап                           | Что происходит                                                            |
|--------------------------------|---------------------------------------------------------------------------|
| 1. Получение данных            | Данные поступают из источников                                            |
| 2. Определение схемы           | Движок определяет структуру: поля, типы, формат, новые/изменённые колонки |
| 3. Профилирование данных       | Проверяются значения, заполненность, уникальность                         |
| 4. Поиск чувствительных данных | Ищутся ФИО, телефон, email, адрес, диагноз, анализы, платежи, документы   |
| 5. Классификация               | Каждому полю или файлу присваивается класс конфиденциальности             |
| 6. Проверка политик            | Policy Engine решает, можно ли грузить данные дальше и в какой слой       |
| 7. Трансформация               | Данные маскируются, псевдонимизируются или обезличиваются                 |
| 8. Загрузка в хранилище        | Данные попадают в нужный слой хранилища                                   |

### Метрики эффективности классификации
| Метрика                 | Что показывает                                                      | Как помогает оптимизации                              |
|-------------------------|---------------------------------------------------------------------|-------------------------------------------------------|
| Classification coverage | Доля полей/файлов с присвоенным классом                             | Показывает, сколько данных осталось без классификации |
| Precision               | Доля корректно найденных чувствительных данных среди всех найденных | Снижает ложные срабатывания                           |
| Schema changes count    | Сколько новых/изменённых полей появилось                            | Контроль изменения источников                         |
| Time to classify        | Сколько времени занимает классификация                              | Показывает производительность движка                  |
| Policy violation count  | Сколько загрузок нарушили правила                                   | Показывает проблемные источники                       |
| Sensitive data in layer | Попадали ли PII/MEDICAL в аналитические витрины                     | Метрика безопасности                                  |

### Масштабируемость решения
| Механизм                                              | Как помогает                                          |
|-------------------------------------------------------|-------------------------------------------------------|
| Горизонтальное масштабирование classification workers | Можно параллельно обрабатывать большие batch-загрузки |
| Очередь задач                                         | Позволяет разгрузить ETL и классификацию              |
| Партиционирование                                     | Разеление данных по дате, источнику, филиалу          |
| Кэш правил классификации                              | Ускоряет классификацию                                |
| Kubernetes autoscaling                                | Увеличивает число worker-подов при росте нагрузки     |
